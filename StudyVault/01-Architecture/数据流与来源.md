# 数据流与来源

#arch-data-flow

## 数据持久化分层

| 数据 | 存储/所属组件 | 如何参与输出 | 失效边界 |
| --- | --- | --- | --- |
| 私人原文、长期记忆、情绪 | `companion.sqlite` / 本机后端 | 受预算与角色限制的上下文 | 纠正、遗忘、来源版本 |
| 群事件、实际回执、经历 | `social.sqlite` / 独立社交服务 | 授权经历通过 sync 发布 | 群策略、人设、来源依赖 |
| 社交只读缓存 | `social-cache.sqlite` / 桌宠 | 新鲜、允许共享的摘要 | epoch、cursor、revision、过期 |
| 已送达 QQ 待同步事件 | `social-outbox.sqlite` / 迁移包 | 重试同事件同步，不重发 QQ | 事件去重与实际发送回执 |
| 项目索引、任务、命令回执 | 工程领域及 T3 持久化层 | 按需引用、状态回读、UI 投影 | 项目/任务绑定、命令 ID、事件序号 |
| 配置与激活 | 各平台 `.local/` 及受限凭据引用 | 决定可用操作和运行包 | revision、指纹、权限 |

数据库名来自项目架构文档；不同组件内部的实际文件位置由平台与配置决定，不把此表当作当前机器已存在的数据清单。

```text
输入原文 -> 带身份/时间的来源 -> 持久化
  +-> 当前请求 -> 预算选择 -> 模型 -> 再校验 -> 输出
  +-> 后台提案 -> 来源/版本验证 -> 派生记忆或摘要
遗忘/撤回 -> 来源失效 -> 派生记录/缓存失效 -> 旧输出阻止
```

## 三种版本不要混用

| 标识 | 含义 | 不能替代 |
| --- | --- | --- |
| TurnScope / generation | 当前轮次或宿主连接归属 | 记忆来源有效性 |
| revision / expectedRevision | 快照或配置比较版本 | 实际平台送达回执 |
| epoch + cursor | 社交数据库身份与增量进度 | 群共享策略许可 |
| commandId + sequence | 工程命令去重与事件位置 | 最终任务完成证据 |

## 导入、回放与重新允许共享

私人历史导入有独立来源、去重和暂停机制；助手文本本身不能证明用户事实。重新导入相同来源不能复活已遗忘内容。社交重新允许共享会按其协议重新发布该群现存经历，不能类推为恢复已遗忘的记录。T3 历史回放和新事件订阅分开，需要协调游标与订阅时机。
