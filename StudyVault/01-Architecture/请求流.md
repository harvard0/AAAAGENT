## 私人聊天端到端

```text
宿主 command
 -> BackendSession.receiveLine (解析与装配)
 -> DesktopRuntime (创建/取消轮次)
 -> DialoguePipeline.run
 -> 语音: 感知/转写；文字: 直接取文本
 -> 工作处理? --是--> 任务/确认路径
 -> 保存 user -> 判定记忆请求与隐私边界
 -> 独立后台: enqueueTurn
 -> JsonDialogueProvider.prepare (冻结外部引用与请求帧)
 -> foregroundContext / assembleContext (使用同一帧计数)
 -> JsonDialogueProvider.reply
 -> scope/上下文/社交引用重新校验
 -> 保存 assistant -> reply 事件
 -> text: replied；voice: TTS -> 播放事件 -> played
```

对话核心也保留其他端口组合的兼容路径，应按实际装配分支阅读。普通整理异步执行；遗忘或纠正需要立即施加隐私边界。发布结果前和播放过程中检查仍在继续。

## 工程执行端到端

```text
工作文本 -> DesktopWork 草稿/任务卡 -> 用户确认
 -> DesktopWorkbench / Gateway -> 命令台账
 -> client-runtime RPC -> ws.ts -> 规范化命令
 -> OrchestrationEngine.dispatch -> 事件/命令回执
 -> ProviderCommandReactor -> ProviderAdapter -> 实际 Agent
 -> ProviderRuntimeIngestion -> 领域事件/投影/订阅
 -> 工作台 UI 和桌宠状态通知
```

`accepted`、事件 `sequence` 与“任务成功”有不同含义。派发结果不明时先按命令 ID 回读；展示页面返回管理页也不等于取消工程任务。

## Windows QQ 到私人上下文

```text
现有 QQ 机器人 -> 真实平台发送成功 + replied
 -> record_delivery -> 持久 outbox -> participations
 -> 摘要任务 -> 经历/来源 -> sync 授权增量
 -> 原子提交缓存与游标 -> 新鲜引用 -> 对话请求
 -> 模型返回前后 assertCurrent
```

通用社交协议先生成待发回复、再 claim/ack；Windows participations 记录其他机器人已经发出的回复，两者不能混为一次重复发送流程。
