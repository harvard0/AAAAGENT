# 管理服务与配置（重要度 ★★★）

#module-management #pattern-ports

## Purpose

提供本机管理 UI 与受控 HTTP 操作，统一查看和修改记忆、模型、项目、任务及表现设置。路由通过能力端口调用各领域，配置更新使用版本比较。

## Public Interface

| 接口或入口 | 行为 |
| --- | --- |
| `startManagementServer` | 返回 origin、token、带片段认证的本机入口 URL 及 close |
| `startRuntimeManagement / ManagementRuntime` | 绑定领域端口并提供快照 |
| `GET /api/snapshot / PUT /api/settings` | 状态读取及带 expectedRevision 的设置写入 |

## Internal Flow

```text
同源管理页面 -> /api 路由
  -> Host/Origin + Bearer 校验 -> JSON/字段校验
  -> 记忆/配置/项目/任务能力端口 -> 持久化
  -> 有限业务结果或脱敏错误 -> UI
```

监听 127.0.0.1 的动态端口。API 读取要认证，写入还要求当前 Origin；静态资源使用白名单与 CSP。setup 模式在桌宠尚未运行时只暴露设置能力，不能假定所有运行期 API 已就绪。设置保存不会修改当前 effective 配置：快照区分 revision 与 effectiveRevision，以 pending 和 applyOn: restart 表示等待重启。未知错误统一转为 internal_error，不把数据库正文或内部栈直接发给浏览器。统一外观 postMessage 接缝仅传导航与主题意图，不授予工程命令权限。

## Configuration

| 字段或环境 | 用途与限制 |
| --- | --- |
| `expectedRevision` | 修改设置必须匹配当前版本，冲突返回 409 |
| `mode: setup / runtime` | 决定首配与运行期可用能力 |
| `uiRoot / presentationAssets` | 管理静态资源来源 |
| `token / nativeFrameOrigin` | 会话认证及明确允许的工程 frame 来源 |

## Testing

```powershell
Set-Location code/desktop-pet
npm.cmd run build
node --test dist/tests/management/balance-http.test.js
```
