# 角色社交服务与缓存（重要度 ★★★）

#module-social #pattern-provenance

## Purpose

在独立数据库中维护角色的群聊参与经历，并向私人桌宠提供经过授权的只读摘要缓存。真实发送回执、身份归属、共享策略与撤回共同决定可用上下文。

## Public Interface

| 接口或入口 | 行为 |
| --- | --- |
| `startSocialServer / SocialWorker` | 启动服务与后台模型工作 |
| `SocialStore` | 接受事件、确认投递、同步与撤回 |
| `LocalSocialConnection.sync / capture / assertCurrent` | 只读增量缓存及模型前后有效性校验 |
| `POST participations（Windows）` | 接收已送达的 event / reply / receipt |

## Internal Flow

```text
通用: events -> 生成回复 -> claim -> 平台发送 -> ack -> 经历摘要
Windows QQ: 平台已发送 -> outbox -> participations -> 经历摘要
  -> social.sqlite -> sync(epoch/cursor/upsert/delete)
  -> social-cache.sqlite -> 授权且新鲜的引用 -> 私人对话模型
```

channel、sync、admin 使用不同 Bearer 凭据；浏览器 Origin 请求拒绝。事件同 ID 同正文去重，同 ID 异正文冲突。claim 只取得发送租约，只有平台真实送达才能 ack；unknown 等待核查。缓存每 15 秒拉取，maxAgeMs 不得超过 300000 毫秒；按页将数据与游标原子提交，数据库 epoch 改变时拒绝混用。共享撤回即使没有新经历也生效，遗忘沿直接来源依赖撤回派生摘要。社交服务不读取私人 companion.sqlite。

## Configuration

| 字段或环境 | 用途与限制 |
| --- | --- |
| `roleId / characterId / endpoint / syncToken` | 本地连接绑定；不把所有用户角色并成一个身份 |
| `maxAgeMs / maxContextCharacters` | 缓存新鲜度上限 5 分钟；引用字符预算上限 12000 |
| `maxRequestsPerDay` | 社交服务默认每日最多 100 次模型请求 |
| `group.enabled / shareWithOwner / expectedRevision` | 策略启用、共享与版本比较更新 |

## Testing

从项目根目录开启新的终端后执行：

```powershell
Set-Location windows/code/desktop-pet
npm.cmd run test:social
```

协议、缓存、回执与权限合成测试；云端联调及真实 QQ 投递是另外的验证。

命令为学习入口，本次建库未执行项目测试或真实服务调用。模块构建与平台要求见 [[构建测试与发布]]。
