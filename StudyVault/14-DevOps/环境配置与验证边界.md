# 环境配置与验证边界

#config-environment #test-validation

## 从配置到运行

```text
选平台源码 -> 对应 Node/依赖 -> 授权资源与服务配置
 -> 运行包与激活指纹 -> 本机预览/类型检查
 -> 定向合成测试 -> 真实模型 -> 实体设备/渠道
```

顺序是学习与排错路径，不表示本次已经执行过各步。正式运行入口、账户和素材准备遵循相应平台安装文档。

## 配置归属

| 配置 | 应在哪里理解 | 容易混淆的边界 |
| --- | --- | --- |
| 供应商/费用/容量 | [[模型适配与媒体链路]] | 不同 operation 可以走不同服务 |
| 私人记忆策略与遗忘 | [[私人记忆与上下文]] | 参数回退不复活遗忘数据 |
| 社交角色/群共享/三类 token | [[角色社交服务与缓存]] | sync 不具备修改权限 |
| 工程运行包/项目/执行器 | [[工作执行与项目上下文]] | accepted 与完成分开 |
| 窗口/资源/设备 | [[桌面宿主与平台边界]] | 资源占位可构建不代表渲染成功 |
| 本地后端路由 | [[Windows本地模型网关]] | health 不证明模型就绪，单项本地不代表全部离线 |

源码中 credentialFile 可能要求项目外的受限凭据；这是产品配置规则。本次建库没有访问那些位置，也没有复制模板中的绝对凭据占位路径。

## 如何陈述证据

| 已看到的证据 | 可以说明 | 仍不能说明 |
| --- | --- | --- |
| 源码和脚本 | 预期控制流与命令范围 | 当前服务已运行 |
| TypeScript/构建 | 对应源码能编译 | 原生宿主与设备可用 |
| 合成测试 | 特定边界和反例受保护 | 模型语义正确或平台送达 |
| 历史模型报告 | 当时版本与配置的结果 | 本次快照重新通过 |
| 模拟渠道回执 | 回执后的逻辑可联调 | 实际 QQ 群收到消息 |
| 本学习库自检 | 笔记结构及引用一致 | 产品整体通过验收 |

`docs/PLATFORMS.md`、`windows/docs/LOCAL-LLM.md` 与 `windows/docs/SOCIAL_MEMORY.md` 包含历史失败和未验证项；学习时保留日期和范围，不能把“计划”“支持的代码路径”和“实际成功”混写。
