# 构建测试与发布

#config-environment #test-validation

## 工具链与执行位置

| 子项目 | Node 要求/包管理 | 依据 |
| --- | --- | --- |
| 根目录桌宠 | Node >=20.19，npm | `code/desktop-pet/package.json` |
| Windows 桌宠/本地模型 | Node >=22.12.0，npm | 各自 package.json |
| T3 工作区 | Node ^24.13.1，pnpm 11.10.0，实际运行工具 vp | `t3-source/package.json` 与 development runbook |
| Windows CI | Node 24.19.0 | `.github/workflows/windows.yml` |

版本要求并不表示本机依赖已安装。根目录无统一 package.json，不能在项目根直接 npm test。每个代码块从项目根的新终端开始。

## Windows 桌宠：安装、预览与类型检查

```powershell
Set-Location windows/code/desktop-pet
npm.cmd ci
npm.cmd run check
npm.cmd run dev
```

dev 是离线预览路径，显示预览回复不代表真实对话。真实服务需要按照 `windows/README-WINDOWS.md` 补配置、激活和授权资源，不能将预览结论升级为模型验收。

## 测试组的实际范围

| 目录中的命令 | 实际选择/性质 |
| --- | --- |
| 桌宠 `npm test` | 构建后默认收集 dist/tests/memory 与 providers |
| 桌宠 `npm run test:release` | 选择指定 memory/providers/wechat/integration/management 回归文件 |
| Windows `npm run test:windows` | 构建后收集 tests/windows 下 mjs |
| Windows `npm run test:social` | cloud、participation 与打包 smoke 合成检查 |
| Windows `npm run test:windows:ui` | 构建并启动受控桌面 smoke |
| 本地模型 `npm test` | 网关的合成测试 |
| 本地模型 `npm run doctor` | 依赖本机配置/后端的诊断，不等同于效果测试 |

选组依据是两套 `tools/run-tests.mjs` 与 package.json。模块笔记列出对应定向测试；本次没有安装依赖或运行这些项目命令。

## T3：使用实际开发工具

先按 `t3-source/README.md` 的 Install vp 和 `docs/operations/development.md` 准备 vp。在 t3-source 内：

```powershell
Set-Location t3-source
vp i
vp run typecheck
vp run --filter @t3tools/web test
vp run dev --home-dir .study-dev-state
```

最后一条会创建开发状态并启动服务；仅在准备启动时执行。使用启动器输出的配对 URL 和实际端口，不硬编码旧凭据或 origin。工作区构建/格式检查使用 `vp run build`、`vp run fmt:check`；原生包还依赖平台工具链。

## CI 与发布边界

根 `.github/workflows/windows.yml` 在 windows 路径变更时启动 Windows job：安装依赖、重建 SQLite/esbuild、安装 Electron，再跑 windows 与 release 组；没有供应商凭据、私有素材、付费推理或设备检查。另一个 `windows/.github/workflows/windows.yml` 是平台目录内的文件，不能把它当作根工作流的额外必跑 job。

根目录 Mac 固定引擎是 Codex 0.160.0、DSH 0.2.0-rc.2 与 Node 24.13.1 的平台清单。源码存在、构建通过和历史真实任务是不同证据。移动端只保留部分构建来源，不自动获得 SDK、签名或应用商店发布能力。
