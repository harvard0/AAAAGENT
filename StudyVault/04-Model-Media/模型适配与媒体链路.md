# 模型适配与媒体链路（重要度 ★★★）

#module-model-media #pattern-ports

## Purpose

将稳定的对话、感知和 TTS 能力映射到供应商请求，并处理媒体捕获、播放、计费授权与完整请求预算。结构合法、HTTP 成功和回答正确是三个不同的检查层次。

## Public Interface

| 接口或入口 | 行为 |
| --- | --- |
| `ProviderTransport.request / EndpointConfig / CallAuthorizer` | 网络请求、端点配置、调用前授权和结算 |
| `JsonDialogueProvider.prepare / countContext / reply` | 冻结请求帧、按同一帧计数、校验响应 |
| `TurnCapture / CaptureDriver` | 设备能力接口；媒体对象保留轮次归属 |
| `inputBudgetInfo / countRequestInput` | 计算有效输入限额并保守估算完整请求 |

## Internal Flow

```text
CaptureDriver -> TurnCapture -> 感知/ASR -> 文本
上下文 + 冻结时钟/社交引用 -> JsonDialogueProvider
  -> ProviderTransport -> 授权 -> HTTP -> 校验与结算
回复文本 -> TTS provider -> 音频 -> 设备播放回执
```

prepare 冻结时钟、表现和可用社交引用，countContext 与 reply 使用一致请求帧；发送前以及结果返回后均要校验社交引用。有效容量是目标、API 输入限额和上下文窗口减预留输出三者的最小值。countRequestInput 使用序列化请求字节及额外保守开销，并非精确 tokenizer；不能把该计数当作账单 Token。ASR、对话、记忆、摘要与 TTS 可以选不同服务，启用一种本地能力不会自动迁移其他调用。

## Configuration

| 字段或环境 | 用途与限制 |
| --- | --- |
| `models.<operation>.provider / model / endpoint` | 每类操作单独选服务 |
| `credentialFile / budgetMode / limitMicros` | 受限凭据引用及调用额度；示例不提供真实凭据 |
| `inputTokenLimit / outputTokenLimit / contextWindowTokens` | 容量与预留，字段必须经过配置校验 |
| `outputMode / 媒体作用域` | 决定是否合成、播放及接受设备回执 |

## Testing

从项目根目录开启新的终端后执行：

```powershell
Set-Location code/desktop-pet
npm.cmd run build
node --test dist/tests/providers/adapters.test.js dist/tests/media/browser-drivers.test.js
```

供应商适配器与浏览器设备替身测试；不代表真实音色或模型答案质量。

命令为学习入口，本次建库未执行项目测试或真实服务调用。模块构建与平台要求见 [[构建测试与发布]]。
