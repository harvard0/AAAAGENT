# T3服务端与事件编排（重要度 ★★★）

#module-t3-server #pattern-event-stream

## Purpose

承载工作台类型化 RPC、命令编排、事件存储与投影，并通过供应商适配器驱动实际 Agent 会话。Effect Service 描述能力，Layer 提供运行实现。

## Public Interface

| 接口或入口 | 行为 |
| --- | --- |
| `makeCli / serve / start 等子命令` | 命令行启动及管理入口 |
| `WsRpcGroup / ORCHESTRATION_WS_METHODS` | 共享 Schema 约束的 RPC 方法 |
| `OrchestrationEngine.dispatch / readEvents / streamDomainEvents` | 串行派发、历史回放及新事件流 |
| `ProviderService / ProviderAdapter` | 隔离 Codex、Claude 等供应商运行细节 |

## Internal Flow

```text
CLI/Server runtime -> 鉴权后的 RPC -> ws.ts
  -> normalizeDispatchCommand -> OrchestrationEngine.dispatch
  -> 命令去重/事件持久化 -> 投影与领域流
  -> ProviderCommandReactor -> ProviderAdapter -> Agent
  -> ProviderRuntimeIngestion -> 领域事件 -> 客户端订阅
```

命令返回 sequence 表示已持久化的事件序号，不是 Agent 整项任务完成。readEvents 读取历史，streamDomainEvents 只包含新事件；需要无丢失订阅时注意先订阅再启动消费者的接口。服务端将运行事件转为可投影的活动，UI 不应仅根据某次 RPC 返回值推断最终状态。

目录分组：orchestration/persistence/provider 是执行主链；project/workspace/git/vcs/sourceControl/pullRequest/review/checkpointing 支撑工程操作；auth/environment/device/cloud/relay 支撑环境与接入；terminal/preview/mcp/process 支撑工具与进程；observability/diagnostics/resourceTelemetry/telemetry/usage/stream/background 负责运行辅助。desktopUpdate 与 cli 负责更新及入口。assets、utils、testUtils 是资源或辅助代码。

| 字段或环境 | 用途与限制 |
| --- | --- |
