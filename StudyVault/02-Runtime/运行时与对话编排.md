# 运行时与对话编排（重要度 ★★★）

#module-runtime #pattern-ports

## Purpose

把桌面命令转换成有作用域的对话轮次，协调输入、聊天或工作分流、持久化和输出。核心逻辑依赖能力接口；具体供应商和设备在装配层接入。

## Public Interface

| 接口或入口 | 行为 |
| --- | --- |
| `BackendSession.receiveLine(line)` | JSON 行协议入口；先校验 channel 与命令形状 |
| `DesktopRuntime` | 管理活动轮次与 TurnController，不让模型等待阻塞取消 |
| `DialoguePipeline.run(input, signal, captured?)` | 返回 played / replied / handled / cancelled / failed |
| `DialoguePorts / TurnScope` | 以能力接口和轮次归属约束跨层调用 |

## Internal Flow

```text
桌面 command -> BackendSession.receiveLine -> DesktopRuntime
  -> DialoguePipeline.run -> 感知(语音) / 文字
  -> 工作处理或私人聊天 -> 记忆/上下文 -> 模型回复
  -> 保存 assistant -> reply 事件 -> TTS/播放(语音输出)
```

语音输入必须有捕获内容和结束证据，文字轮次拒绝携带麦克风或相机捕获。独立后台记忆路径先保存用户输入，再排队维护并读取可用前台上下文；普通后台失败不等于前台失败。模型返回、落库和播放期间仍需校验 scope 与上下文版本，过期轮次不能继续输出。文本渠道直接完成 replied，不产生音频播放事件。

## Configuration

| 字段或环境 | 用途与限制 |
| --- | --- |
| `outputMode` | voice 或 text；text 禁止设备捕获与播放 |
| `PET_TRIAL_CONFIG / PET_TRIAL_ACTIVATION` | 启动器传给后端的配置与激活文件位置 |
| `backgroundMemory / memoryLifecycle` | 装配时与对话使用同一 memory port，不能混接不同实例 |

## Testing

从项目根目录开启新的终端后执行：

```powershell
Set-Location code/desktop-pet
npm.cmd run build
node --test dist/tests/integration/backend-session.test.js
```
