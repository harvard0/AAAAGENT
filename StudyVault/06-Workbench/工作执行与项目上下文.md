# 工作执行与项目上下文（重要度 ★★★）

#module-workbench #pattern-idempotency

## Purpose

把工作意图转为可确认任务，再关联项目、执行器和回执。私人陪伴上下文按需获取工程引用，完整任务、会话和状态保留在工作记录中。

## Public Interface

| 接口或入口 | 行为 |
| --- | --- |
| `DesktopWork` | 实现 DesktopWorkPort，协调意图、计划与确认 |
| `ForwardReceipts` | 持久确认与转发状态，不替代执行器实际状态 |
| `WorkbenchTurnGateway / WorkbenchInteractionGateway` | 校验绑定、派发命令并读取实际命令回执 |
| `ProjectContextAssembler` | 按项目组装资料和引用 |

## Internal Flow

```text
用户工作请求 -> 意图/计划 -> 草稿与任务卡 -> 用户确认
  -> 项目与现有任务绑定 -> 命令台账 -> T3/Codex/DSH
  -> 实际回执或 unknown -> 状态回读 -> 桌面通知
项目索引/工程记录 --按需引用--> 陪伴上下文
```

accepted 表示命令被接受，不证明任务完成。派发超时或结果不明不能直接创建第二个任务，应按 commandId 回读。清除 unknown 提醒只改变提醒确认，不改变执行状态。项目根、任务 ID、执行器和供应商绑定必须保持一致。engine-lock.json 固定的是项目运行包版本，不能把上游任意新版本直接替换进去。

## Configuration

| 字段或环境 | 用途与限制 |
| --- | --- |
| `engine-lock.json target / versions / digests` | 根目录运行包为 darwin-arm64；Windows 使用自己的清单 |
| `runtimeMode` | approval-required 或 auto-accept-edits，属于执行器配置 |
| `projectId / workspaceRoot / existingTaskId` | 工作台档案和任务绑定 |
| `AAAAGENT_T3_PREPARED_DIR / AAAAGENT_T3_NODE_EXECUTABLE` | 启动器从校验过的运行包建立环境 |

## Testing

从项目根目录开启新的终端后执行：

```powershell
Set-Location code/desktop-pet
npm.cmd run build
node --test dist/tests/harness/desktop-work.test.js dist/tests/workbench/native-bridge.test.js
```

任务确认、回执和桥接测试；固定运行包与真实执行器任务另验。
