# 快速上手

#dashboard #onboarding

## 第一步：明确源码范围

本仓库根目录的 `code/` 与 `t3-source/` 是 Mac 构建来源，Windows 实现在独立 `windows/` 下。本库先从根目录共享概念读起，再单独解释平台差异，不能把两端当作相同文件副本。

1. 打开 [[系统架构]]，说明陪伴、社交、工程三个数据边界。
2. 按 [[请求流]] 各追踪一条聊天和工作请求。
3. 查看 [[数据流与来源]]，区分私人、群聊、缓存与任务记录。

## 第二步：在 Windows 安全预览

从项目根目录的新 PowerShell 终端开始，先检查运行环境：

```powershell
node --version
npm.cmd --version
Set-Location windows/code/desktop-pet
npm.cmd ci
npm.cmd run check
npm.cmd run dev
```

预览使用隔离离线输入，示例回复不能用于证明云端推理；缺少模型素材时查看明确的资源缺失提示。真实服务的手动配置见 `windows/README-WINDOWS.md` 与 `windows/docs/SETUP.md`。macOS 用户使用 `docs/SETUP.md`，不要照搬 Windows 宿主构建。

## 第三步：选一个领域，做五道练习

| 角色 | 推荐阅读顺序 |
| --- | --- |
| 后端与记忆 | [[运行时与对话编排]] → [[私人记忆与上下文]] → [[模型适配与媒体链路]] |
| 社交接入 | [[微信与QQ渠道适配]] → [[角色社交服务与缓存]] → [[社交HTTP接口]] |
| 工程执行 | [[工作执行与项目上下文]] → [[T3服务端与事件编排]] → [[T3共享合同与协议包]] |
| 界面和宿主 | [[T3客户端与共享状态]] → [[桌面宿主与平台边界]] → [[管理服务与配置]] |
| 本地能力 | [[Windows本地模型网关]] → [[模型适配与媒体链路]] |

模块笔记结尾有对应练习入口。先闭卷回答 trace/config/debug，再设计 extend，最后用 analysis 检查边界理解。

## 第四步：小范围验证

按 [[构建测试与发布]] 选择对应模块测试。不要把桌宠默认 npm test 误认为全仓覆盖。所有真实模型、账号、素材与设备检查需记录实际平台、版本和结果。
