# 桌面宿主与平台边界（重要度 ★★★）

#module-desktop #pattern-ports

## Purpose

提供窗口、渲染、设备与进程桥接，连接桌宠界面和可信 Node 后端。macOS 原生桌宠、Windows Electron 桌宠和 T3 Electron 工作台是三个需要分别理解的宿主。

## Key Files

| 项目相对路径 | 定位行 | 职责 |
| --- | --- | --- |
| `code/desktop-pet/desktop/native/main.swift` | 1 | macOS AppKit/WebKit 原生桌宠 |
| `windows/code/desktop-pet/desktop/electron/main.mjs` | 45 | Windows 窗口、可信 IPC 与后端生命周期 |
| `windows/code/desktop-pet/desktop/electron/transport.mjs` | 5 | Node 后端传输及代次隔离 |
| `t3-source/apps/desktop/src/main.ts` | 1 | T3 Electron 工作台主进程 |
| `docs/PLATFORMS.md` | 1 | 两套源码、资源和验证差异 |

## Public Interface

| 接口或入口 | 行为 |
| --- | --- |
| `桌宠 DesktopToBackend / BackendToDesktop` | 由后端桥接合同约束命令、事件和设备响应 |
| `Windows pet:desktop / pet:shell IPC` | 限定消息来源、主 frame、代次与命令形状 |
| `BackendConnection` | 后端进程、就绪状态与 generation |
| `T3 desktopBridge / preload` | 工作台有限平台能力 |

## Internal Flow

```text
桌宠 Web 界面 -> 宿主桥 -> Node 后端 -> 领域逻辑
设备/渲染事件 <- 宿主 <---------------- 后端事件
macOS: Swift + AppKit + WebKit
Windows: Electron main + preload + BackendConnection
T3: 独立 Electron 工作台宿主 -> Web 客户端 -> T3 Server
```

Windows IPC 检查 sender、mainFrame 与 pet://app/index.html，并匹配 connection.generation，旧进程消息不能控制新连接。窗口偏好、角色资源和后端业务数据各有职责。缺少 Live2D SDK/素材时编译成功不等于模型显示成功；Swift、权限弹窗、实体设备及长期负载也不能用 TypeScript 编译结果替代。根目录与 windows 依赖、状态和二进制不能相互复制覆盖。

## Testing

从项目根目录开启新的终端后执行：

```powershell
Set-Location windows/code/desktop-pet
npm.cmd run test:windows
npm.cmd run test:windows:ui
```

Windows 受控平台/界面检查；第二条需要可用桌面会话，不证明真实设备或 macOS 通过。

命令为学习入口，本次建库未执行项目测试或真实服务调用。模块构建与平台要求见 [[构建测试与发布]]。
